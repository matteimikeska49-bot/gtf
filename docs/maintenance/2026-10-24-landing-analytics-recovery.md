## Confirmed PR defects fixed in this update

1. The candidate's narrow URL filter stripped `yclid`, `ysclid`, `gclid` and other supported advertising identifiers, and rejected legitimate UTM values containing seven consecutive digits. Numeric campaign IDs and bounded, explicitly allowlisted click IDs now survive address sanitization and the actual first Metrica hit. Supported identifiers: `yclid`, `ysclid`, `gclid`, `dclid`, `gbraid`, `wbraid`, `gad_source`, `gad_campaignid`, `_openstat`; standard UTM includes source platform, creative format and marketing tactic. Unknown fields and email/URL syntax in UTM values are still excluded. Duplicate keys are normalized so a second, unvalidated value cannot bypass filtering.
2. Consent after internal SPA navigation could lose the entry campaign/search marker before the first collected pageview. Validated entry attribution remains in current-document memory before a choice, and reaches the first consented GA4/Metrica view. There is no optional persistent storage or tracking before consent, and no replay of pre-consent pageviews.
3. Metrica referrer had been reduced to the origin. The first view now receives a sanitized document referrer with path and allowed attribution; subsequent SPA hits receive the previous tracked URL as `referer`.
4. An ignored cookie write over an existing grant could undo an explicit refusal; cookie getter exceptions could also stop the bootstrap. Cookie access now fails safely, a current-document refusal overrides an older grant, and a timestamped necessary refusal fallback preserves denial locally across reload when storage is available. Withdrawal remains GA-disable + Metrica destruct + optional storage/cookie cleanup + safe reload. Repeated sync does not repeat withdrawal. If both cookie writes and local storage are unavailable while an old grant remains readable, current-document tracking is stopped without reloading into that old grant; persistence cannot be guaranteed by inaccessible storage.

These are **candidate PR defects**, not additional explanations of the October production drop: PR #20 has not been deployed. No consent relaxation, new conversion event or GTM/account setting change is introduced. The existing PR's single explicit Metrica hit owner (`defer:true`) covers initial, push/replace and popstate views. GA4 retains its single config/native history owner. The unmapped `seo_page_view` emission remains removed; existing CTA event definitions remain unchanged. Presence of both GTM and gtag is not itself evidence of duplication; runtime event counts are the verification.

Yandex documents why first-view labels matter: [traffic labels](https://yandex.ru/support/metrica/ru/general/source-tags), [ysclid search attribution](https://yandex.com/support/metrica/ru/general/search-query-sup). Google documents [auto-tagging](https://support.google.com/google-ads/answer/3095550?hl=en) and [aggregate ad identifiers](https://support.google.com/analytics/answer/16479993?hl=en). These support preserving validated advertising parameters, not bypassing consent or allowing personal data in campaign labels.
